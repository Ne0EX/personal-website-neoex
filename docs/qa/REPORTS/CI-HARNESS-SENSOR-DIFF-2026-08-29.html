Root causes and repair intent

Private CI denominator

HEAD ran six configured rails directly while the authoritative config contained 22. A hand-maintained workflow could silently omit new enforcing rails. The new runner enumerates .rails | keys[] in lexical order and emits one JSONL record per key plus a summary.

Context confused with availability

Task/event/browser rails cannot be proven in shared CI merely because their scripts exist. The new metadata explicitly separates required deterministic runs from context-only, embedded, deferred-browser, advisory, and stub outcomes.

Hidden soul-atom failure

set -e aborted at the TypeScript command substitution when the audit returned exit 1. The shell now captures the exit deliberately so structured violations reach stdout and the hook log.

Build and Vercel prerequisites

CI lacked explicit public Supabase inputs, and an unanchored tools/ ignore could also remove lib/netra/tools. The workflow validates public variables; root-anchored ignore rules preserve nested application source.

Fixture/linter race

Temporary Git repositories were created under the repository root, allowing ESLint to discover a fixture while the test removed it. Fixtures now use the operating system temp directory and clean up there.

Evidence boundary

The runner’s JSONL is deterministic machine evidence, but this HTML is a manually produced QA snapshot. CI does not yet generate or upload an equivalent HTML sensor-delta artifact automatically.
