### S1 · Canopus — fix the CLAUDE_TASK_ID wiring bug

**root cause:** README "Installation" wires `PreToolUse(Write|Edit|MultiEdit)` to `bash .claude/hooks/pre-task.sh "$CLAUDE_TASK_ID"`. Claude Code does not export `CLAUDE_TASK_ID` to hook subprocesses, so the argument expands to empty string; `pre-task.sh` correctly exits 2 on missing `TASK_ID`, which blocks the tool call.

**fix:** `pre-task.sh` is conceptually "before a TASK starts" — it should be invoked manually by an agent at task start (when the agent knows its task_id), not by Claude Code on every Write/Edit. The README "Installation" example is the wrong wiring.

**input**
- `.claude/settings.json` (currently contains the broken wiring)
- `.claude/hooks/README.md` (Installation section §9–35 has the wrong example)

**output**
- `.claude/settings.json` — remove the `PreToolUse(Write|Edit|MultiEdit)` block entirely. Preserve `SessionStart`, `PreToolUse(Agent)` for `on-dispatch.sh`, `PostToolUse(Write|Edit|MultiEdit)` for `post-edit.sh`, and `Stop` for `sign-work.sh`. Use Bash heredoc, not Edit/Write.

  Note on `Stop` → `sign-work.sh "$CLAUDE_TASK_ID"`: this has the same CLAUDE_TASK_ID problem. Decide one of:
  - (a) leave it in, document that it's a no-op until `CLAUDE_TASK_ID` is set in the agent's env (sign-work.sh will exit 2 on every Stop event and the user sees a noisy error)
  - (b) remove it entirely; agents invoke sign-work.sh manually before handoff (current de facto pattern)
  - (c) wrap with `if [ -n "$CLAUDE_TASK_ID" ]; then bash sign-work.sh "$CLAUDE_TASK_ID"; fi` — silent no-op when unset

  Choose **(c)** unless you have a specific reason to prefer another option. Document the choice in your return handoff.

  Similarly for `PostToolUse(Write|Edit|MultiEdit)` → `post-edit.sh`: post-edit.sh doesn't take task_id as arg (it uses `WL_TASK_ID` env), so it should be fine. But verify by reading the script and confirming it doesn't bail on missing env.

- `.claude/hooks/README.md` — update the "Installation" section to reflect reality:
  - Remove the `PreToolUse(Write|Edit|MultiEdit) → pre-task.sh` example.
  - Note that `pre-task.sh` is **invoked manually** by an agent at task start, after reading its assignment.
  - Update the `Stop` example to use the (c) pattern above.
  - Add a "Why no auto pre-task hook?" callout explaining the CLAUDE_TASK_ID limitation — useful for any maintainer who reads the README and wants to "re-enable" the auto-wire.

**acceptance**
- `.claude/settings.json` valid JSON; `PreToolUse(Write|Edit|MultiEdit)` block absent; other blocks preserved.
- Polaris re-runs `Edit` on STATUS.md (this very file) after your fix lands — must succeed (verify in your return handoff that the fix has been applied to disk so this test will pass on the next session).
- README "Installation" section no longer instructs maintainers to wire `pre-task.sh` on `PreToolUse`. The replacement narrative is clear.
