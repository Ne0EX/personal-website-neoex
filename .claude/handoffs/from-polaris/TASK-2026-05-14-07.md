# TASK-2026-05-14-07 · Interactive browser capability for the whole roster

## scope

TASK-06 wired the first half of rendering capability: `scripts/render-html.sh` (HTML → PNG, content-agnostic). This task wires the second half: **interactive browser access via an MCP server**, available to every subagent in this project, so future Sirius / Betelgeuse / Algol / Vega / Arcturus work can hover, click, scroll, run Lighthouse, and inspect live state — not just look at static frames.

The decision to go path B (heavy but complete) over A1+A2+A3 (incremental docs) was made by Peat on the access-map analysis Polaris presented. "หนักแต่จบ" — build the durable infrastructure once.

After this task ships, the **single commit** that closes the rendering-capability wave includes: TASK-06 (review + render-html.sh + 22 PNGs + REVIEW.md) + TASK-07 (MCP browser + docs + bundle fetcher).

## slices

### S1 · Canopus — select + install + wire a Playwright MCP server

**input**
- Existing project MCP wiring (none yet for browser; some MCPs from `claude.ai_*` and `plugin_*` are session-level, not project-level)
- Existing `.claude/settings.json` (must not regress)

**research + decide:**
- Pick between (a) official Anthropic/MCP-ecosystem Playwright server, (b) community Playwright MCP, (c) custom thin wrapper. Recommend by tradeoff. Tradeoff axes: tool coverage (navigate/click/screenshot/evaluate/console-logs/keyboard/Lighthouse), maintenance burden, security scope, install footprint.
- Choose **headless mode by default** with **optional headed mode** for Peat-side debugging.

**output**
- MCP server installed (npm/uv whatever its packaging is) — pinned version recorded in `docs/harness/RENDERING.md`
- `.claude/settings.json` extended with an `mcpServers` block pointing at the chosen server. Existing `hooks` block MUST stay intact.
- Smoke test: dispatch a tiny subagent (Canopus self-dispatch via a separate one-off, or Polaris-side test) and confirm browser MCP tools appear in its tool list, navigate to `http://localhost:3000` (or any reachable target), and round-trip a result.
- If the MCP server requires per-tool permission entries in settings, add minimal scoping — start tight (localhost + the Peat-authorized Anthropic design domain) and document how to widen.

**non-goals**
- Do NOT install a headed-by-default browser (no GUI flicker for Peat)
- Do NOT wire any auth-bearing browser session (no logged-in profiles; every session starts clean)
- Do NOT add browser MCP to user-level `~/.claude/settings.json` — project-scoped only, so other projects on this machine are unaffected
- Do NOT pre-grant unbounded URL access — the team works on Worldline plus a small explicit allowlist for now

**acceptance**
- Smoke-test subagent (any role) can call at least: `browser_navigate`, `browser_screenshot`, `browser_evaluate` (or equivalents), and receive valid responses
- `.claude/settings.json` valid JSON; SessionStart + Stop + PostToolUse + PreToolUse(Agent) wiring preserved
- An existing session test confirms no regression on Edit/Write (TASK-05 fix stays good)
